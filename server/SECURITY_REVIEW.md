## Verified controls

Owner checks bind every private resource access to its authenticated workspace. Passwords are bcrypt-hashed; session and capability tokens have 256 bits of randomness. Session identifiers and recovery codes are stored as hashes. Account recovery invalidates all previous sessions. HTTP mutation routes validate Origin; private routes also validate CSRF. Production uses the Firebase-compatible `__session` cookie with Secure, HttpOnly, SameSite=Lax and no Domain attribute. Request payloads, workspace aggregates, projects, history, monthly usage and daily AI/demo attempts are bounded. Exports omit credentials and capability tokens. Client projections omit internal cost, analysis and audit records. Model suggestions never determine acceptance or pricing.

The suite currently has 36 passing backend tests across three files, with clean TypeScript checking. This includes production cookie forwarding and CSRF, canonical redirects, owner-confirmed project deletion at quota limits, monthly quota renewal, repeated saves/shares, reserved decision capacity, stale AI results and failed optional enrichment persistence. A live Firestore 9.2 smoke verified nested aggregate serialization, hash-chain verification after retrieval, conflicting native transactions and rollback against the named `pactshift` database. All smoke records were removed. A deployed Cloud Run smoke also authenticated an isolated demo, created a request, received grounded Vertex output from `gemini-2.5-flash-lite`, and deleted the temporary workspace successfully. The new Firebase Hosting rewrite requires a fresh hosted smoke after deployment.

## Explicit deployment and product boundaries

- Cloud Run service-account authorization passed a deployed demo/create-analysis/delete workflow; the separate native concurrency smoke used an existing authorized CLI identity.
- Real Stripe checkout/portal execution requires merchant credentials and configured prices. Signed webhook behavior is locally tested with test signatures; this is not evidence of live sales.
- Client decisions identify a capability-link holder’s supplied name, not a verified signer. The product should describe this as a decision record.
- One owner per workspace is supported. Email verification, MFA, teammate roles and external audit anchoring are future features.
- Workspace documents are intentionally bounded. High-volume customers require migration to separate project/event collections before limits can increase.
- Local JSON supports one server process. Production startup requires Firestore and HTTPS.
