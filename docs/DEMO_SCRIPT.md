## Capture setup and retake guidance

- Record at 1920×1080 or higher, 16:9, with a clean browser window and readable text. Hide unrelated tabs, notifications, password-manager prompts, keys, and personal information.
- Use a newly created isolated demo workspace. The sample is fictional: Northstar Studio, Forma Architecture, and the Forma website.
- Keep the owner view in one tab and open the generated client offer in a separate tab or private window. This is a demonstration of both roles, not two actual people.
- Rehearse once before recording. Check the deployed engine label, data persistence, share flow, and final screen against the release version.
- Use the generated narration with an explicit AI narration disclosure. A human recording can use the same third-person script. Remove only dead time; retain the actual decision and resulting state transition on screen.
- Keep the sample-data indicator visible when showing project numbers. Use captions. Background music is optional and should never compete with speech.

## Verbatim narration

Read only the paragraphs in this section. These match the final third-person AI voice segments. The script works with either the labeled rules engine or the optional Vertex engine.

> Pactshift was built by Shivam Gupta. An agency agrees to build a website. Halfway through, the client asks for one more thing. The request changes, but the budget and delivery plan often don't. Pactshift turns that conversation into a choice everyone can see, and an agreement the project actually follows.
>
> Let's take a real workflow using fictional sample data. Northstar Studio is building this website for Forma Architecture. The fixed budget is twelve thousand dollars. The agreed work totals ninety-six estimated hours. Now the client wants Spanish-language pages, estimated at twelve hours, with the translated copy supplied by the client.
>
> The request sits beside the saved scope. The analysis helps the owner review what is changing, and the interface shows which engine produced it. AI can assist here, but it does not decide what the client owes. The owner confirms the effort. The server calculates the fee from the project's rate: twelve hours at one hundred and twenty-five dollars is fifteen hundred dollars.
>
> Charging more is one option. But the client may care more about the launch date and a fixed budget. So the agency can offer an exchange. This resource library is planned for sixteen hours and hasn't started. We can replace it with the twelve-hour language addition. Work already underway, locked deliverables, and dependencies constrain what can be offered.
>
> The agency shares the proposal and opens the client view. The client doesn't need to create an account. They can see the addition with its fee and schedule impact, the exact deliverable exchange, or the option to defer. They also see the assumptions. There is no surprise invoice hiding behind an approval button.
>
> In this demonstration, the fictional client chooses the exchange. They enter a name, acknowledge the terms, and confirm the choice.
>
> Back in the agency workspace, this is the important part: the agreement changed. The resource library has been exchanged for the Spanish-language pages. The budget is still twelve thousand dollars. The delivery date is unchanged. Total estimated work moves from ninety-six to ninety-two hours, and the new baseline records the decision.
>
> That is four hours of planned capacity preserved, not four hours of revenue. The system also keeps previous baselines and a linked decision history. Version checks protect against stale approvals, and repeated acceptance cannot duplicate the new work. The owner can export the workspace record. The client acknowledgement records a decision; it does not independently verify the signer's identity.
>
> Pactshift is built for small agencies that need this conversation handled clearly. The proposed subscriptions start with a free plan, then twenty-nine dollars for Studio and seventy-nine dollars for Agency, with defined stored-project and analysis allowances. Client review has no seat charge, and Pactshift takes no cut of an agency's approved work.
>
> This is a pre-validation product, with no claimed customers or revenue. Shivam developed Pactshift with substantial AI assistance, and the next step is testing this workflow with real agency owners and their clients. The goal is simple: when the request changes, help both sides agree on what changes with it.

## Operator checks for a retake

1. Start a fresh demo so the request is still a draft and the project is at baseline one.
2. Review the request; confirm 12 hours, the 16-hour resource library swap, supplied-copy assumption, and the two-day add-on schedule adjustment.
3. Save before sharing. The public offer is a snapshot of that proposal; do not attempt to edit it after sharing.
4. Open the offer link and confirm it excludes internal cost rate, unrelated requests, and private audit details.
5. Make the swap decision only once during the take. A retake needs a fresh demo.
6. Verify the new baseline in the owner tab. If the display needs a refresh, show it naturally.
7. Keep the subscription section accurate: say “proposed,” and do not imply a live payment succeeded unless a real configured test has been recorded and labeled as a test.

Pricing counts stored projects, including archived records. All plans have a 720,000-byte serialized workspace bound; project limits are 30 requests, 80 deliverables, 50 baselines, and 100 audit events. Keep the pricing screen's limits visible. Do not add “unlimited approvals” or “unlimited history” to the narration.
